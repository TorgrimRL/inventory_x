# Project Retrospective Documentation

This directory serves as the record of our team's agile process and continuous improvement throughout the development lifecycle.

## Agile Methodology
Our team followed a structured Agile approach, conducting retrospectives at the conclusion of every sprint.

### The Start-Stop-Continue Framework
We utilized the "Start-Stop-Continue" model to facilitate open discussion and ensure actionable outcomes:
* **Start:** New behaviors or technical practices we tought would be beneficial.
* **Stop:** Activities that proved to be bottlenecks or counter-productive.
* **Continue:** Successful workflows that added value and were maintained across subsequent sprints.

### Documentation Process
Every retrospective followed a standardized structure:
1. **Previous Action Item Review:** Verifying completion of tasks from the prior sprint to ensure accountability.
2. **Brainstorming Board:** Capturing raw feedback in the Start-Stop-Continue table.
3. **Deep-Dive Discussion:** Elaborating on specific friction points or ideas raised during the brainstorm.
4. **Action Item Assignment:** Defining concrete tasks for the next sprint, each with an owner and a specific deadline or scope.

## Sprint Narrative & Evolution
Our documentation tracks the team's transition from a disorganized startup phase to a disciplined, documentation-focused closing phase:

* **Phase 1 (Sprint 1-2):** Focused on "norming." We established meeting habits and resolved early technical friction regarding merge conflicts and PR response times.
* **Phase 2 (Sprint 3):** Focused on "performing." We introduced quality-centric practices like Test-Driven Development and integrated external feedback with user testing.
* **Phase 3 (Sprint 4-5):** Focused on "closing." We implemented a feature freeze to focus high-quality documentation and report finalization.
